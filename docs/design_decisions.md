# Архитектурные решения и проектные выборы (Design Decisions)

Этот документ описывает ключевые инженерные решения, ограничения и архитектурные компромиссы, заложенные в пайплайн обработки лекций (`lecture-to-notes`).

---

## 1. Аппаратные ограничения (4 GB VRAM)

- **Контекст:** Проект разработан с расчётом на запуск на потребительском ноутбуке с видеокартой NVIDIA RTX 3050 Ti (4 ГБ VRAM, Windows 11).
- **Решение:** 
  - Модель транскрибации GigaAM-v3 не способна эффективно и стабильно обрабатывать длинные аудиофайлы целиком в рамках 4 ГБ VRAM (вызывает CUDA Out Of Memory).
  - Пайплайн принудительно нарезает аудио на короткие **20-секундные чанки** (`config.yaml` -> `audio.chunk_seconds`).
  - После обработки каждого чанка выполняется принудительная очистка кэша CUDA (`torch.cuda.empty_cache()`) и сборка мусора (`gc.collect()`), что предотвращает утечки памяти и падения.

---

## 2. Обработка аудио и нарезка на чанки

- **Инструментарий:** Использование **FFmpeg** для конвертации входных видео/аудиофайлов в канонический формат (моно WAV, 16 кГц), требуемый моделью GigaAM.
- **Восстановление таймкодов:** Поскольку аудио делится на фиксированные отрезки, при финальной сборке транскрипта таймкоды каждого слова/сегмента смещаются на абсолютное время старта соответствующего чанка.
- **Фильтрация тишины:**
  - Реализована проверка максимальной абсолютной амплитуды чанка: `np.max(np.abs(chunk)) < cfg["audio"]["silence_threshold"]`.
  - Пустые/тихие чанки пропускаются без вызова инференса модели, экономя время и вычислительные ресурсы.
  - *Нюанс:* Использование `np.max(np.abs(...))` вместо RMS может приводить к редким ложноположительным срабатываниям на тихую речь с пиковыми шумами, однако это простое и быстрое решение, достаточное для учебных и лекционных аудиоматериалов.

---

## 3. Модель транскрибации (GigaAM-v3)

- **Версионирование:** Используется модель GigaAM-v3, зафиксированная на конкретном коммите из официального репозитория Salute-Developers в `requirements.txt`. Это обеспечивает воспроизводимость результатов и защищает от неожиданных ломающих изменений в upstream.
- **Токен авторизации:** Для работы с моделью требуется токен Hugging Face (`HF_TOKEN`), проверяемый при импорте модуля `src.transcribe`.

---

## 4. Генерация конспекта (LLM через Google Gemini)

- **Провайдер:** Интеграция с Google Gemini API с использованием легкой и быстрой модели `gemini-3.5-flash-lite`.
- **Отключаемость:** Генерация конспекта по умолчанию отключена в конфигурации (`summarize.enabled: false`), что позволяет успешно использовать пайплайн локально только для получения транскрипта без необходимости обязательного наличия `GEMINI_API_KEY`.
- **Промптинг:** Промпт настроен на создание академического структурированного конспекта с сохранением таймкодов в формате `[ЧЧ:ММ:СС]`.

---

## 5. Тестирование и верификация

- **Инструмент:** `pytest`.
- **Фокус тестов:** Модульные тесты проверяют доступность FFmpeg, корректность загрузки конфигурации (`config.yaml`), логику обработки аудио (включая обработку ошибок конвертации) и работу модуля суммаризации.
- **Окружение:** Проект оптимизирован под запуск в виртуальном окружении Python (`.venv`) на Windows 11 с поддержкой раздельных инструкций по установке для CUDA-ускорения (`requirements-cuda.txt`) и чистого CPU (`requirements.txt`).
